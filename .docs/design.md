# cider lab — Design Guidelines

個人開発アプリ、技術記事、OSSライブラリのドキュメントを集約する日本語サイトのデザイン規約。

現行の `src/styles/global.css`、`src/styles/articles.css`、主要コンポーネントを基準にする。配色と構成は既存実装を継承し、可読性・操作性に関する数値は今後の整備にも適用する要求値とする。実装済み・検証済みを示す監査結果ではない。

## 1. デザインの方向性

- 落ち着いた緑を主役に、夕日のようなオレンジで温かさを加える。
- Sauce Labsを参照した、大きな見出し、明確なCTA、余白のある構成、開発を連想させるビジュアルを、このサイトの配色に合わせる。
- 個人の制作活動と技術的な信頼感を両立する。本文と成果物を中心に据える。
- 日本語で内容を把握でき、使い方・記事本文・リポジトリへ迷わず進める。
- 装飾はヒーローとプロジェクト紹介に集中させ、記事とドキュメントでは読みやすさを優先する。

参照対象はSauce Labsのデザイン。getdesign.mdの一覧・検索サイト自体のUIを再現しない。

### 配色ルール

- 画面の大部分は白と淡いミント。濃い緑は操作・見出し・ブランド要素に使う。
- オレンジは小面積のアクセントに使う。本文リンクや通常の主CTAは緑にする。
- オレンジ背景の文字は `ink`。小さい白文字を載せない。
- 通常テキストは背景とのコントラスト比4.5:1以上を確保する。透過色を含め、実際の組み合わせで確認する。
- 色だけで選択・成功・失敗を表さず、文言・アイコン・状態属性を併用する。
- エラー状態は意味が伝わる文言と必要な専用色を設計する。ブランドのオレンジを一律に警告色へ転用しない。
- ライトテーマを基準にする。ダークテーマを追加する場合は全トークンと本文・埋め込みをまとめて設計する。

## 3. タイポグラフィと日本語組版

### フォント

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Hiragino Kaku Gothic ProN",
  "Noto Sans JP", "Yu Gothic", Meiryo, sans-serif;
--font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

システムフォントを優先する。フォント名の指定だけではWebフォントを配信しない。外部フォントを追加する際は日本語フォントの転送量と表示遅延を確認する。

| 要素                     | 文字サイズ                     | 行高・扱い                   |
| ------------------------ | ------------------------------ | ---------------------------- |
| ヒーロー見出し           | `clamp(2.1rem, 4.1vw, 3.6rem)` | `1.6`、太字、字間 `-.05em`   |
| セクション見出し         | `clamp(1.7rem, 3vw, 2.4rem)`   | `1.45`、太字、字間 `-.025em` |
| 記事ページ見出し         | `clamp(1.65rem, 3vw, 2.4rem)`  | `1.6`                        |
| カード見出し             | `1.25–1.5rem`                  | 日本語の複数行を許容         |
| 一覧の記事タイトル       | `1rem`                         | `1.625`程度、全文表示        |
| 通常本文                 | `1rem`                         | `1.85`                       |
| 記事・ドキュメント本文   | `1rem`以上                     | `1.95`                       |
| 説明文・操作ラベル       | `.875rem`を基準                | 長文は行高 `1.8`以上         |
| 日付・タグ・リアクション | `.75rem`以上を目標             | 補助情報でも判読性を確保     |
- 日本語の本文に大きな字間や両端揃えを適用しない。
- 強い字詰めは大見出しだけに限定する。
- 英字の小見出しは短いラベルに限定し、字間 `.14em`を使える。主要見出しと操作は日本語にする。
- 日本語は通常の禁則処理で折り返す。全体への `word-break: break-all` は使わない。
- 長いURLやパッケージ名には `overflow-wrap: anywhere` を使い、レイアウトのはみ出しを防ぐ。
- 固定のヒーローコピーは意味のまとまりで改行できる。CMSの記事タイトルには表示幅依存の改行を保存しない。
- 一覧の記事タイトルと要点を省略しすぎない。行数固定でカードの高さを揃えるより、内容を読めることを優先する。
- 日付表示は日本時間で統一し、`time` 要素に機械可読な日時を付ける。

## 4. レイアウトと余白

| 要素                 | 基準                                     |
| -------------------- | ---------------------------------------- |
| 全体コンテナ         | `max-w-7xl`、中央寄せ                    |
| 横余白               | モバイル20px、`md`以上32px、`xl`以上48px |
| セクション上下余白   | 64px、`md`以上96px                       |
| ヘッダー高さ         | 80px                                     |
| カード間隔           | 20–24px                                  |
| カード内余白         | 24–28px                                  |
| 記事本文の最大幅     | 780px                                    |
| 記事の右目次         | `xl`以上で190px                          |
| ドキュメントの左ナビ | `lg`以上で200px                          |
| ドキュメントの右目次 | `xl`以上で170px                          |

余白は4px単位を基準にする。セクション、カード、内部要素の順に余白を小さくし、情報のまとまりを示す。

### レスポンシブ

- `sm: 640px`、`md: 768px`、`lg: 1024px`、`xl: 1280px`を基準にする。
- ヒーローはモバイルで文章→ビジュアルの順、`lg`以上で2列。
- プロジェクトはモバイルで1列、`lg`以上で注目枠と補助枠を `1.65fr / 1fr` に分ける。
- ライブラリはモバイル1列、`md`以上2列。
- 記事一覧はモバイルで日付を上段に出し、`md`以上では日付・タイトル・矢印を横に並べる。
- グローバルナビは `lg`未満でメニューにまとめる。
- 狭い画面の目次は本文前の開閉式にする。
- ページ全体の横スクロールを発生させない。コードと表は専用領域内で横スクロールできる。
- 320px幅、長い日本語タイトル、200%ズームで操作と本文が欠けないことを確認する。

## 5. ホームの構成

1. **ヘッダー**：ブランド、セクションナビ、検索、モバイルメニュー。
2. **ヒーロー**：価値を伝えるコピー、2つのCTA、コードウィンドウの装飾、公開コンテンツ件数。
3. **プロジェクト**：注目する成果物を大きく、その他を補助カードとして配置。
4. **技術記事**：ミント背景。タグ絞り込み、日付、タイトル、概要、外部サービスのリアクション。
5. **OSSライブラリ**：用途、パッケージ名、インストールコマンド、導入ガイド・GitHub・npmへのリンク。
6. **ドキュメントCTA**：淡いピーチの面に、導入ガイドへの主CTA。
7. **About**：制作姿勢、著者、外部プロフィール。
8. **フッター**：濃い緑の面、ブランド、補助ナビ。

公開件数はデータから算出する。記事数やカード数を固定文言として埋め込まない。コンテンツが増えても、カードの高さや順番を個別CSSに依存させない。

### ヒーローの基準コピー

> 小さな不便を、つくる楽しさに。

説明：日々の「ちょっと困った」を、コードで心地よく。個人開発と技術の記録を、ここから。

主CTAは「つくったものを見る」、補助CTAは「技術記事を読む」。オレンジの下線は「つくる楽しさ」に添える。

## 6. コンポーネント

### ヘッダーと検索

- ヘッダーは白を主体とした半透明背景、細い境界線、控えめなぼかし。スクロール時も読める濃さを保つ。
- 検索はボタンと `Ctrl/Cmd + K` で開く。入力、検索結果、該当なし、取得失敗を区別する。
- 検索ダイアログは最大幅576px、最大高さ `80dvh`。背景を暗くし、内部をスクロールできるようにする。
- 開いたら入力へフォーカスを移動し、Escで閉じ、閉じたら起点へ戻す。ダイアログ外へフォーカスを逃がさない。
- スキップリンクを設け、キーボードで本文へ移動できるようにする。

### ボタンとリンク

- 主ボタン：緑背景・白文字。ホバー時は `primary-dark`。
- 補助ボタン：淡い背景・緑の文字と境界線。
- 角丸8px、基本余白は横20px・縦12px。操作対象は44×44px以上を目標にする。
- 本文中のリンクは下線などで周囲の文章と区別する。ホバーだけを手がかりにしない。
- 内部遷移の矢印は `→`、外部遷移は `↗` を基本とする。矢印だけのリンクを作らない。
- 操作は `button`、遷移は `a`。カード内にリンクとコピーボタンがある場合、カード全体をリンクで包まない。
- フォーカスリングは現行のオレンジ3px・オフセット4pxを出発点に、隣接背景での視認性を確認する。必要なら濃い緑や二重リングに調整する。

### カードと装飾

- 通常カードは白背景、1pxの `line`、角丸16px。通常状態の強い影を避ける。
- 影はヒーローの重なるカード、アプリのモック、ダイアログに限定して奥行きを表す。
- 傾きはヒーローのコードウィンドウと小さな装飾カードに限定し、概ね3–6度にする。
- 太陽の円、薄い同心円、コードウィンドウをCSSまたはSVGで構成する。
- 装飾は `aria-hidden="true"`。説明に必要な情報は通常の本文にも記載する。
- PoohMaの紹介では「パスワードヒントを暗号化して保存」という仕様を正確に表現する。

### 記事一覧・リアクション

- 記事一覧は横罫線で区切るリスト形式。タイトルは自サイトの記事本文へリンクする。
- フィルタは丸いチップ。選択状態は緑背景・白文字と `aria-pressed` で示す。
- Zenn・Qiitaのリアクションは本文へのリンクの外側に配置する。
- サービス名、いいね、コメント、Qiitaのストック、取得日時を補助情報として表示する。
- 各サービスの数値を区別し、合算して独自の人気指標にしない。
- 未取得は「件数は未取得」。取得できた0件と区別する。
- 更新失敗時は前回取得値と元の取得日時を表示する。成功していない取得日時へ更新しない。
- 外部リアクションがなくても記事本文は読める構成にする。

### インストールコマンド

- ミント背景、等幅フォント、コピーボタンをセットにする。
- 長いコマンドは折り返さず、コマンド領域だけ横スクロールさせる。
- コピー成功・失敗を短い文言で伝える。成功通知は読み上げにも対応する。

## 7. 記事・ドキュメント本文

- Zenn公式のMarkdownレンダラーと `zenn-content-css` を使い、本文を `.znc.doc-content` にまとめる。
- ブランド調整は本文フォント、リンク色、行高、見出し余白、画像の角丸などに限定する。
- 見出し、リスト、引用、表、コード、数式、注意書き、埋め込みの表示を保つ。
- 技術記事はタイトル、説明、タグ、公開日・必要な更新日、リアクション、目次、本文の順で構成する。
- ライブラリドキュメントはライブラリ名、説明、インストール、本文を中心にする。デスクトップでは左ナビと右目次を付ける。
- 現在のドキュメントは `aria-current="page"` と緑の背景で示す。
- 固定ヘッダーでアンカー先を隠さない。見出しのスクロール余白は7remを基準にする。
- 目次の第3階層は軽く字下げし、過度に深い階層を作らない。
- 画像は本文幅に収め、説明画像には適切な代替テキストを付ける。
- 記事本文の配信にクライアントJavaScriptを必須にしない。

## 8. 動きと状態

- 通常の色・透明度・位置の遷移は150ms程度に抑える。
- ボタンのホバー移動は最大2px程度。本文や一覧を大きく動かさない。
- 自動再生の背景動画や常時動く装飾を基本要素にしない。
- `prefers-reduced-motion: reduce` ではアニメーション、滑らかなスクロール、ホバー時の移動も停止する。
- 検索結果0件、フィルタ結果0件、コピー失敗、リアクション未取得を、それぞれ理解できる文言で表示する。
- キーボード操作、タッチ操作、ホバーのない端末でも主要操作を完了できるようにする。

## 9. 実装規約

- Astro + React + TypeScript + Tailwind CSSを使用する。
- ブランドカラーとフォントはTailwindの `@theme` で定義する。任意の色をコンポーネントごとに増やさない。
- 共通スタイルは `src/styles/global.css`、記事固有のスタイルは `src/styles/articles.css` にまとめる。
- ページ構造と静的な表示はAstroの静的HTMLを基本とし、検索・絞り込みなどの操作部分にReactを使う。
- コンテンツは記事リポジトリとmicroCMSから取り込む。記事の長さ・タグ数・カード数が変化しても成立させる。
- 自サイト本文はMarkdownをビルド時にHTML化する。ホームのReact propsへ全記事本文を渡さない。
- 装飾のために大きな画像やクライアントライブラリを追加しない。本文画像には表示サイズや遅延読み込みを適切に設定する。
- 外部リアクションは取得時点の情報として表示し、ページ閲覧のたびに取得を待たせない。

## 10. レビュー時の確認項目

- 緑の主CTAとオレンジのアクセントが意図した優先順位になっているか。
- 日本語の長い見出し、URL、パッケージ名で表示が崩れないか。
- モバイルで本文と主要CTAが装飾に押し出されていないか。
- 記事・ドキュメント本文の行幅、行高、コード・表のスクロールが適切か。
- キーボードでナビ、検索、目次、フィルタ、コピーを操作できるか。
- 小さい補助文字、半透明色、フォーカス表示に十分な視認性があるか。
- 画像なし、記事なし、検索結果なし、リアクション未取得でも意味が通るか。
- 新しいコンテンツを追加するたびにCSS修正を必要としていないか。
